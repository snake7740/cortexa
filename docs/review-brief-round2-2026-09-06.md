# Cortexa × AML 第二期 · 外发评审简报（2026-09-06）

> 用途：把本项目完整上下文交给外部平台/专家评审换取新思路。文档自包含——不需要仓库访问即可核验。期望帮助形式见 §7。

## 0. 项目一句话
Cortexa：面向 Agent Memory Leaderboard(AML) 的长期记忆系统，只暴露 Add(写入)/Search(返证据) 两操作；回答与评分由平台统一。处于第二期(9/20 开放滚动至 10/31)备赛期；官方 Key 与数据尚未到位，本简报基于赛制规则、官方解读案例与本地实验撰写。

## 1. 已知规则（固定件，所有参赛者相同）
- 协议：Add/Search 两操作；Answer/Judge 固定(GPT-4o-mini 系)；Search 只回证据(禁止生成答案)；top_k 上限 100；无命中允许空数组。
- 判官判词(可核验，官方六 pipeline 内)：typo 容忍；冲突时 prefer the most recent supported memory；列表题全项且 no-extras；时间粒度严格(相对/绝对不可混)。
- 能力维度：A 显式事实召回 / B 多跳组合 / C 时间与事件 / D 治理(含删除合规) / E 个性化 / G 上下文学习与执行 / H 认识论安全(拒答/最小披露)。
- 学术榜约束：须绑定代码/commit、可复现审查；禁跨样本共享状态、禁硬编码公开题；未明示禁止会话内状态(但 gaming 风险自担)。
- 第二期：报名 9/20 00:00 UTC+8，滚动接入评测至 10/31，成绩计划 11 月中旬；每轮提交有私有回执。
- 部署红线(我们自查)：user_id 全程隔离；评测数据 30 天删除；评测内容不留日志；确定性/可复现优先；检索路径零非官方模型调用。

## 2. 已具备能力（实测，全部本地/自证）
- 工程面：golden 契约测试、隔离/WAL/FTS5、TTL+eval 脱敏、/health 自证、质量闸(check.py + retrieval-gate 掉>2% 即红)、stress_smoke(add p95 108ms / search p95 10ms, 1200 条)。
- 检索默认：fts(bigram)+hash 向量 双路 RRF，rule/chapter boost，FSRS 调制(首测中性=官方首轮零贡献，如实标注)，缺席闸，options 拼接。
- 治理 v2：词边界信号/问句与未来打算不取代/属性槽；supersede+retcon 审计链；真实误藏案例 2/21 修复归零；soft 档与内容驱动 forget(R3) 就绪。
- 评测工具链：本地回放器(开关矩阵)、转换器(LongMemEval-S/InMind)、recall_miss 卡、judge_v1 判答夹具(待 key)；会话级 RRF/查询规划/时间锚定/年份过滤/recency 仲裁(RAR) 全部默认关原型。
- 本地代理实测(标口径，非官方)：LME-S 21 题 top5 hash 12/21(hit@1=4)、minilm 8/21(0)；InMind 125 direct 54.4%(hash)/52.0%(minilm)、indirect 20.8%/13.6%；token 等预算 cap25 = -21% tok 代价 -6.4% hit；检索质量闸基线 hit@1=.909 等。

## 3. 已知弱点与负结果（请勿重复建议）
- A 面释义弱(direct 54%)与间接路由弱(indirect 21%)——已测；真实稠密未进默认(朴素 minilm 并入伤 top1，负)。
- C 时序弱(相对时间类 channel-miss 复发)；F2 解析器就绪未接线。
- 单旋钮饱和证据：RRF 权重档中性、长消息切块负、实体/语义默认开负、邻接只填余量中性、规划器/会话 RRF 在本地自述语料不可分。
- 上届与官方案例负结果：图结构、集合感知重排、廉价信号门控交换 top(P5 四信号全负)。
- 仿真层(FSRS/Dreaming/RARE/维度地板)审计结论=托底不拔高；数学公理=正确性护栏非增益——参赛叙事已按工程口径。

## 4. 待突破点（开放问题，附：已试/想关联什么）

### Q1 读时状态仲裁(已立 RAR 原型；求更优冲突检测与副作用控制)
- 背景：判官 prefer most recent；AMI 零治理 D 第一(37.95)；我们治理 v2 硬隐藏曾有误藏(已修)。RAR=不删旧、冲突簇按 event_ts 显式把最新排前、旧态作支撑。
- 已试：subject 簇+共享词/实体判冲突；弱加成不足以翻序，改显式重排(排序后执行)。
- 求问：免解析/免模型的 subject-attribute 冲突键如何更稳？旧新并存对列表题 no-extras 的量化风险与缓解？token 预算内"当前态+历史支撑"最优配比(TREC 250→50 字节先例)？

### Q2 A 面释义与路由(固定稠密对所有人一样的前提下还能做什么)
- 背景：InMind direct 54%、indirect 21%；参考 A 56.8-57.8 靠真实稠密+改写。我们 Search 无 LLM 预算、本地无 key；minilm 朴素并入实测伤 top1。
- 已想：会话内访问层学习(再巩固)——但用评测问题训练访问层在学术榜有 gaming 风险，倾向放弃；稠密候选门控(A/B/C 方案)待数据。
- 求问：检索派还有哪些不依赖模型、不依赖固定稠密差异的释义/路由手段？如何在不碰红线前提下利用查询历史？typo/词形还原轻量做法是否值得进默认？

### Q3 C 时序(开放榜天花板 24.6 vs 工业 56-60——检索派为何集体做不好时间)
- 背景：判官时间粒度严格、相对/绝对不可混；我们有 event_ts、F2 相对→绝对解析器就绪(月30/年365 近似)、年龄衰减/年份过滤默认关。
- 求问：检索派内部破 C 的最小可靠件？纯 Python 日历锚定精度够不够(平台给 timestamp 与日期线索)？事件顺序题是否需"顺序索引"类结构而非检索排序？

### Q4 滚动窗口多轮私评闭环(方法学求教)
- 背景：9/20-10/31 可多轮提交，每轮有私有回执(带维度分)。计划：假设→回执→失败桶归因→单变量改动→重交。
- 求问：多轮调优在私有回执上的过拟合/多重比较风险怎么控？每轮题集是否固定(平台同题多轮？)如何用少轮次最大化信息(主动实验设计)？

### Q5 延迟-准确预算档(要不要学 ReFind 慢档换准确)
- 背景：ReFind #2 用 agentic 慢档(单次 vs 多轮在长上下文 -20.4)；我们默认 10ms；官方按 Slow/Medium/Fast 标注、Accuracy 榜独立。P5 证明廉价信号交换 top 不可靠。
- 求问：确定性"追加召回"门控(低流畅/完整性词/时间标记触发第二遍)是否值得做？还有哪些不依赖 LLM 的深检触发信号？慢档在官评中的隐性代价证据？

### Q6 无 key 阶段的判答近似(如何低成本逼近官方评分)
- 背景：judge_v1 夹具就绪需 OPENAI key；本地无 key。
- 求问：可信的开源判答/判官替代(本地小模型按 ACCURACY 提示词)与官方 GPT-4o-mini 的一致性经验？样本量多小才够当开关裁决？

### Q7 工程与规模(自托管约束下的边界)
- 背景：SQLite+FTS5+内存向量；官方约 150M 字符量级；单机自托管 Docker；检索需确定性可复现。
- 求问：该量级 FTS/向量/治理全扫的已知拐点与结构建议？在不得引入外部记忆服务约束下，sqlite-vec/独立 BM25 索引等自托管件是否值得？默认关旋钮 10+ 的发布面治理最佳实践？

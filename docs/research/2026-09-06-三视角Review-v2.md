## 视角一：赛制（目标函数还能怎么被利用）

固定件不变：Add/Search、≤100 证据、Answer+Judge=gpt-4o-mini、prefer most recent、
列表 no-extras、时间粒度严格、七维 A-E/G/H、隔离/禁共享状态/禁硬编码/代码复现审查。
**本版更新点：**

1. **官方评测角色降级为"外部验证"**（外部复核 v3 §2 采纳）：Full 次数与 Light 可用性
   未经细则证实前，滚动窗口不再当"反复调参通道"。这对策略的含义是**单次提交的信息量
   上升**——RC 必须是"全默认能力都有成对证据"的冻结版，而不是实验中间态。
2. **Search 三变量成立**：membership / order / **packaging**。packaging 是新的可动面：
   判官只吃证据文本，同样一组证据槽，槽内放单条原文 vs 原文+前文邻接，会改变 Answer
   能看到的指代消解与支撑链——C/G 类题（会话内指代、事件顺序叙述）最敏感。我们已把
   packaging 做成回放层参数（Q8），默认 raw 零变化。
3. **双通道 A/B 面**：options 双通道（题干主查询+选项低权副通道）vs G1 拼接是官方
   选择题形态下的纯检索面实验——题干词面弱、选项含证据实体是 InvMem 已证明的有效面。
4. **规则坑登记表已固化**：契约迁移全链路教训 + Rule Freeze v1 一问单（10 格），
   填表触发=9/20 细则；9/20 前不再改解释口径。

## 视角二：榜单（把谁做对了什么、缺口在哪、如何挤进前列）

既有档案不变：外挂族开源榜 45±0.2（InvMem/ReFind/AMI/CHM 一阶）；冠军碎片化（7 维
冠军散 4 系统、前 3 差 0.22、前 8 差 1.1）；官方基线=安全冠军 67.7（拒绝即护分）；
C 轴开源 18-24.6 vs 工业 56-60（同一判官，检索派普遍没做对——结构性窗）；
AMI 反直觉=D 第一靠"零治理+全保留+时间戳"（读时排序价值>写入删除）；ReFind #2=慢档
agent 多轮检索（延迟换完整性可上榜）。
**本版更新点：**

1. 榜单缺口排序（我们的押注不变但更精确）：
   - C 轴：检索派内没人系统性做对时间——日历锚定(F2 v2)、event_ts+session_ordinal、
     R4 年份过滤现在都是"默认关但正确实现"的件；缺的是**多题时间语料成对裁决**。
   - D 轴：RAR 冲突键 v2 已消化 False Conflict 反例；"当前态在前+历史支撑"与判官
     prefer most recent 同构——差临门一测（Treatment 2: keep-one-predecessor）。
   - A 轴释义：InMind direct 54.4% 是硬伤，但**固定稠密下无模型手段接近饱和**——
     只余词形/typo 低耗件与 options 双通道可试；更大的 A 面收益要等判答层/官方尺。
2. 我们不押（维持）：图/证据图、仿真巩固、跨查询学习、LLM 改写——v3 外部复核的
   停止清单与我们负结果档案互证，分差 0.22 级的前列竞争靠的是**零退化+无短板**。
3. 榜位语义：本地代理分不与官方换算；若现在提交=落中段偏后（不猜名次）——差的是
   两把官方尺（判答正确性、官方数据），不是组件数量。

## 视角三：IT 架构（组件/接口/确定性/规模/发布面）

现状架构（v3 §18 与 mechanism-status 一致）：RAW 不可变 → FTS/向量/元数据(时间) →
Search(查询理解+候选召回) → RRF → 时间过滤 → RAR → packaging → TopK → 平台 Answer。
**本版更新点：**

1. **确定性默认不变**：packaging（回放层）与 options 双通道（服务层开关默认关）都不进
   默认路径；检索默认档现在 10+ 旋钮全关，新增两个都带独立开关与单测。
2. **层位纪律**：packaging 是"证据呈现层"实验——它不改召回与排序（纯函数不变量已测），
   只在回放统计送答文本量；将来若进默认，应在 server 返回层做（同样不改召回）。
3. **状态面复核**：touch（FSRS）仍是 Search 唯一写操作——参赛档关 touch 的口径不变；
   查询历史学习 = 无（deterministic 默认）。
4. **规模下一个坑位**：1×/2×/4× 官方量级 + user P50/P95 压测（Q7）；WAL/FTS 候选
   饱和与"单用户长历史尾延迟"是迁移 sqlite-vec/独立 BM25 的触发门（未现拐点不迁移）。
5. **发布面治理**：默认关检索旋钮已达 10 项(+回放层 --expand/--packaging 实验开关)——RC 验收把"全默认能力有成对证据"与
   "config v-pin 冻结档"写进 check 脚本旁的发布清单（Rule Freeze v1 一并管）。

## 收敛结论（三视角交汇）

1. 赛制视角把"评测=外部验证"后，**本地回放器+成对实验+实验卡预注册**成为唯一调参面
   ——方法学件（Q4）与检索件同等重要。
2. 榜单视角指出 C/D/A 三个可动面里，**C 与 D 都已有"默认关但正确"的实现，缺语料裁决**；
   A 受固定稠密限制只剩低耗件——排序后真正缺的是判答层/官方两把尺子。
3. IT 架构视角确认所有新件都遵守"默认关+确定性+层位正确+可回滚"，架构收敛方向不变。
4. 下一动作序：9/20 前=本地多题语料(时间/冲突桶) + judge v1 判答(key 到位即跑) +
   压测 1×/2×/4×；9/20=Rule Freeze 填表 + Smoke 契约验证(不做算法调参)；
   Light 若开放=RC→Light→有限校准→冻结→Full。

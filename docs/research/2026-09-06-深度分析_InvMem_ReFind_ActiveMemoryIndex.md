## 1. InvMem（#1 45.06）：从相似度到完整性

管线：细粒度分块 → 稠密检索+BM25 → 加权 RRF → **同会话邻接扩写**。论点：命中最相似的块 ≠ 最有用的记忆；有用=能重建完整上下文（前因后果/是否被验证）。
- 与 Cortexa 对照：分块(整轮存)与稠密+BM25(fts+hash/minilm)与加权 RRF(rule/chapter boost≈加权)都是我们已有件；**缺的正是最后一步同会话邻接扩写**——与本项目『邻接上下文应条件触发』结论及 A 系列 L4 完全同向。

## 2. ActiveMemoryIndex（#3 44.84）：无治理却治理维度第一

设计：仅 CREATE/INSERT OR REPLACE（无 UPDATE/DELETE/合并/显式冲突消解）；每次 Add 存**双份**——原始消息 verbatim（时间戳/说话人/原措辞）+ GPT-4o-mini 抽取的首人称原子事实（ablation 显示抽取增益有限）；检索前把查询改写成『记忆向首人称问题』（近似 HyDE，但生成的是记忆问题而非假设答案），与原查询合并排序；返回 raw 在前、facts 在后。
- 关键反直觉结果：#1 于『新值覆盖/当前状态 54.50』与『矛盾检测/冲突消解 24.79』——**没有任何治理机制**。作者解释：改排名 ≠ 解冲突；保留带时间戳的完整证据让答案模型自己判最近有效，可能优于写入期硬隐藏。
- **对 Cortexa 的当头一棒**：我们刚把治理 v2 做成『误杀防住+真更新仍隐藏旧值』；AMI 说治理维可以零治理登顶。合理解读（两边都对）：治理只有在‘不伤害到达答案模型的信息’时才加分——硬隐藏(SUPERSEDED 不进 Search)是双刃剑：正确时=防陈旧，错误时=证据永久不可见（我们 2/21 误杀案例即此）。
- 附带评测学发现：parent block 扩写的收益在控制返回文本量后基本消失——按条数限 top_k 的评测会奖励‘塞更多 token’的系统；建议报 tokens/query+accuracy。我们回放器应记录证据 token 量作对照。
- 弱项：时序推理 18.35——作者下一步=temporal anchoring→versioned facts，恰好走向我们已有的 valid_from/to+supersede 链。

## 3. ReFind（#2 44.97）：不建结构，让 agent 搜原始记录

论文(2608.12888)：对 MemoryAgentBench ~2800 题，**58.2 mean > HippoRAG 2(53.2)**（统一 gpt-4o-mini 骨干）；LongMemEval-S/M 93.2±3.3/89.3±6.0(GPT-5-mini)。设计：原始对话不改动，词法(BM25)轮粒度索引，ReAct 式迭代关键词搜索+四个聊天原生控件（会话感知排名融合/局部上下文展开/时间收窄/跳过已检会话），独立推理阶段作答。论点：**结构化记忆的收益大部分能被‘可控搜索原始记录’回收，且零 LLM 建索引**。
- 权衡：把计算从写入期挪到查询期——检索质量换每查询延迟/token；AML Search 端点是单次调用，ReFind 的『多轮内部搜索』需塞进一次 Search 响应(会吃延迟与 token 预算)。
- 配套基准 **InMind**（隐式关联盲点：问养猫、史上有百合花——相似度搜不到但性命攸关）= 我们 channel-miss 大类(数量/亲属/跨词)与上届文章 I(桥接)的精确学术版；未来可直接当多跳/关联能力的回放靶场。
- 评论区要点（Nyx533）：『search 也是记忆——用状态换延迟；真正分水岭是问题类型：状态类问题(被打断前我正要做什么)检索层答不了』——支持我们 retain 状态类机制(supersede/会话态)而不是全押检索。
